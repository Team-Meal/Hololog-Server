# CI/CD 파이프라인 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions + GHCR + self-hosted runner를 이용한 CI/CD 파이프라인 구축 — PR 시 자동 테스트, main merge 시 Docker 이미지 빌드·push·배포 자동화

**Architecture:** 단일 `cicd.yml` 워크플로 파일에서 `test` → `build-push` → `deploy` 3개 job을 순차 실행. `test`는 PR/push 모두, `build-push`와 `deploy`는 main push 시에만 실행. 배포 서버에 설치된 self-hosted runner가 GitHub에 polling하여 작업을 가져오므로 방화벽 인바운드 포트 오픈 불필요.

**Tech Stack:** GitHub Actions, GHCR (`ghcr.io`), Docker (멀티스테이지 빌드), docker-compose, eclipse-temurin:21

---

## 파일 구조

| 파일 | 역할 |
|------|------|
| `Dockerfile` | 멀티스테이지 빌드 — build 단계(JDK+Gradle)에서 JAR 생성, runtime 단계(JRE)에서 실행 |
| `docker-compose.yml` | 배포 서버에서 컨테이너 실행 관리 — 이미지, 포트, env_file, restart 정책 |
| `.github/workflows/cicd.yml` | CI/CD 워크플로 — test / build-push / deploy 3개 job |
| `.gitignore` | `.env` 항목 추가 — 민감 정보 git 추적 방지 |

## Task 1: Dockerfile 생성

**Files:**
- Create: `Dockerfile`

- [ ] **Step 1: Dockerfile 작성**

`Dockerfile`을 프로젝트 루트에 생성한다.

```dockerfile
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY gradle gradle
COPY gradlew .
COPY build.gradle.kts .
COPY settings.gradle.kts .
COPY src src
RUN chmod +x gradlew && ./gradlew bootJar -x test

FROM eclipse-temurin:21-jre AS runtime
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

> **왜 멀티스테이지?** build 단계의 JDK, Gradle 캐시, 소스코드는 최종 이미지에 포함되지 않는다. runtime 단계는 JRE + JAR만 포함하여 이미지 크기를 대폭 줄인다.  
> **`-x test`**: 테스트는 CI(`test` job)에서 이미 실행됐으므로 Docker 빌드 시 중복 실행하지 않는다.

Expected: `Successfully built ...` 출력, 에러 없음

- [ ] **Step 3: 컨테이너 기동 확인**


Expected: Spring Boot 기동 로그 출력 (DB 연결 실패는 이 시점에서 정상 — 환경변수 미설정 상태)

## Task 2: docker-compose.yml 생성 및 .gitignore 업데이트

**Files:**
- Create: `docker-compose.yml`
- Modify: `.gitignore`

- [ ] **Step 1: docker-compose.yml 작성**

`docker-compose.yml`을 프로젝트 루트에 생성한다.

```yaml
services:
  app:
    image: ghcr.io/team-meal/hololog-server:latest
    ports:
      - "8080:8080"
    env_file:
      - .env
    restart: unless-stopped
```

> **`env_file: .env`**: DB URL, Redis URL, JWT 시크릿 등 민감 정보를 배포 서버의 `.env` 파일에서 읽는다. `.env`는 git에 커밋하지 않는다.  
> **`restart: unless-stopped`**: 컨테이너가 비정상 종료되면 자동 재시작. 수동 `docker-compose stop`으로 내린 경우에는 재시작하지 않는다.

- [ ] **Step 2: .gitignore에 .env 추가**

`.gitignore` 파일 끝에 아래 내용을 추가한다.

```
### Environment ###
.env
```

- [ ] **Step 3: 배포 서버에 .env 파일 생성 (수동 작업)**

배포 서버에 SSH 접속 후 아래 경로에 `.env` 파일을 생성한다.  
(이 파일은 git에 절대 커밋하지 않는다.)

```bash
# 배포 서버에서 실행
mkdir -p /opt/hololog
cat > /opt/hololog/.env << 'EOF'
SPRING_DATASOURCE_URL=jdbc:mariadb://<DB_HOST>:3306/<DB_NAME>
SPRING_DATASOURCE_USERNAME=<DB_USER>
SPRING_DATASOURCE_PASSWORD=<DB_PASSWORD>
SPRING_DATA_REDIS_HOST=<REDIS_HOST>
SPRING_DATA_REDIS_PORT=6379
EOF
```

> 실제 값은 팀 내 비밀번호 관리 도구에서 확인한다.  
> self-hosted runner의 deploy job에서 이 파일을 워크스페이스로 복사해 사용한다.

## Task 3: GitHub Actions 워크플로 생성

**Files:**
- Create: `.github/workflows/cicd.yml`

- [ ] **Step 1: 워크플로 디렉토리 생성**

```bash
mkdir -p .github/workflows
```

- [ ] **Step 2: cicd.yml 작성**

`.github/workflows/cicd.yml`을 생성한다.

```yaml
name: CI/CD

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'

      - uses: actions/cache@v4
        with:
          path: ~/.gradle/caches
          key: ${{ runner.os }}-gradle-${{ hashFiles('**/*.gradle.kts') }}
          restore-keys: ${{ runner.os }}-gradle-

      - name: Run tests
        run: ./gradlew test

  build-push:
    if: github.event_name == 'push'
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GHCR_TOKEN }}

      - uses: docker/setup-buildx-action@v3

      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/team-meal/hololog-server:latest
            ghcr.io/team-meal/hololog-server:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  deploy:
    if: github.event_name == 'push'
    needs: build-push
    runs-on: self-hosted
    steps:
      - uses: actions/checkout@v4

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GHCR_TOKEN }}

      - name: Copy .env from server
        run: cp /opt/hololog/.env .env

      - name: Pull latest image
        run: docker compose pull

      - name: Deploy
        run: docker compose up -d

      - name: Clean up unused images
        run: docker image prune -f
```

> **`cache-from/cache-to: type=gha`**: GitHub Actions 캐시를 Docker layer 캐시로 활용. 소스코드 변경이 없는 레이어는 재빌드하지 않아 빌드 시간이 단축된다.  
> **`docker compose`**: 최신 Docker CLI 플러그인 문법 사용 (`docker-compose` 레거시 명령어 대신).  
> **`cp /opt/hololog/.env .env`**: 배포 서버에 미리 저장된 `.env`를 워크스페이스로 복사. git에 포함되지 않는 민감 정보를 안전하게 주입한다.

- [ ] **Step 1: GHCR_TOKEN 발급**

1. GitHub → 우측 상단 프로필 → **Settings**
2. 좌측 메뉴 → **Developer settings** → **Personal access tokens** → **Tokens (classic)**
3. **Generate new token (classic)** 클릭
4. Note: `hololog-server-ghcr`
5. Expiration: 적절히 설정 (90일 권장)
6. Scope: `write:packages` 체크 (자동으로 `read:packages`, `repo`도 포함됨)
7. **Generate token** → 토큰 값 복사 (이 화면을 벗어나면 다시 볼 수 없음)

2. **New repository secret** 클릭
3. Name: `GHCR_TOKEN`
4. Secret: Step 1에서 복사한 토큰 값 붙여넣기
5. **Add secret** 클릭

GitHub 화면에 표시되는 명령어를 순서대로 실행한다. 예시:

```bash
# 러너 디렉토리 생성

tar xzf ./actions-runner-linux-x64.tar.gz

# 러너 설정 (GitHub 화면의 토큰 사용)
./config.sh --url https://github.com/Team-Meal/Hololog-Server --token <RUNNER_TOKEN>
```

설정 중 runner name, labels 묻는 항목: 기본값(Enter)으로 진행

- [ ] **Step 5: Docker 권한 설정 (runner 사용자가 docker 명령 실행 가능하도록)**
